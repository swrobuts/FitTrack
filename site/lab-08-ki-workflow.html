Der KI-Workflow

Vibe Coding heißt, generierten Code ungelesen zu übernehmen. Agentic Coding heißt, dass das Werkzeug selbst Dateien ändert und Befehle ausführt. Der FitTrack-Workflow ist beides nicht: wenig Autonomie beim Werkzeug, volle Prüfung beim Menschen. Dieses Lab sammelt, was den Chat-Weg tragfähig macht: die Prompt-Vorlage, sechs Regeln für den Betrieb und die Fragen, die an jeden übernommenen Code gestellt werden.

Zwei Achsen, zwei Entscheidungen

Die Begriffe werden oft vermischt, beantworten aber verschiedene Fragen. Die eine Achse ist die Autonomie des Werkzeugs, die andere die Prüfung durch den Menschen.

Einordnung für FitTrack

Vibe Coding ist der richtige Modus, wo nichts davon abhängt: ein Layoutversuch, ein Wegwerf-Skript, das erste Gefühl für eine Bibliothek. Sobald eine Story abgenommen wird, gilt die Prüfstelle. Nicht aus Misstrauen, sondern weil die Gruppe den Code später erklären muss.

Ein tragfähiger Prompt hat vier Teile

Rolle, Kontext, Aufgabe und Randbedingungen. Fehlt einer davon, füllt das Modell die Lücke selbst, oft plausibel, aber falsch.

Review wie ein fremder Pull Request

Übernommener Code wird gelesen wie der Beitrag einer neuen Kollegin: wohlwollend, aber vollständig. Sechs Fragen; bleibt eine offen, ist das bereits ein Befund.

  • Verstanden? Kann ich jede Funktion in einem Satz erklären, ohne nachzusehen?
  • Existiert alles? Gibt es jede importierte Bibliothek und jede aufgerufene Funktion wirklich?
  • Sonderfälle? Leere Liste, fehlender Wert, ungültige Kennung: Was passiert dann?
  • Hartkodiert? Steht etwas im Code, das in die Daten oder die Konfiguration gehört?
  • Testen die Tests? Prüfen sie das Verhalten aus der Story oder nur sich selbst?
  • Passt der Stil? Benennung und Struktur wie im übrigen Projekt, oder ein Fremdkörper?

Übungen

Vier Übungen: Prompt-Teile erkennen, Prompt-Fehler den Regeln zuordnen, die drei Arbeitsweisen unterscheiden, ein Review an einem Codebeispiel.

Zusammenfassung

  • Autonomie des Werkzeugs und Prüfung durch den Menschen sind zwei Achsen. FitTrack wählt wenig Autonomie, volle Prüfung.
  • Rolle, Kontext, Aufgabe, Randbedingungen. Fehlt eines, füllt das Modell die Lücke, plausibel und falsch.
  • Eine Story je Prompt, Fehlermeldungen wörtlich, Erklärung anfordern, nichts Unverstandenes committen.
  • Sechs Fragen an jeden übernommenen Code. Bleibt eine offen, ist das bereits ein Befund.
  • Die typischen Fehler sind bekannt und als Prüfpunkte hinterlegt. Die Tests decken die meisten auf, die Prüfung durch die Gruppe den Rest.
